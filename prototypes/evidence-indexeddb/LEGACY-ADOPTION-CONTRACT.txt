Purpose
Create an unfinished phase 9.2 checkpoint using the unchanged original Field controller
and chapter-space save callback in a disposable old document. Earlier chapter/story
prerequisites and phase 2 entry are explicit synthetic setup. Close that document,
including final pagehide writes. In a cold document, import its exact existing localStorage
values, publish one canonical owner, resume the unchanged Field controller, perform one
native WAIT and durably select its checkpoint. Two fresh reloads must restore this state.
The test does not earn the whole campaign, complete chapter 9, grant points or prove reward
eligibility. It establishes a bounded existing-checkpoint handoff under cooperative
exclusive cold-start conditions. Old uncooperative clients remain a runtime blocker.

Contract boundaries
- A new versioned checkpoint contract; accepted shared-guest-owner/fshared1 semantics stay
  unchanged. Future daily/terminal integration must consume this canonical state or use
  an explicit revision handoff, never run a second independent owner for the same guest.
- Original runtime/model/art/adapter/schema/limits are not modified. There are no imports
  from production index. Native execution uses isolated CI browser contexts only.
- Stable fixture principal /^guest:[A-Za-z0-9_-]{1,64}$/ and three fixed archive identities
  (source, owner, next). Identity is local separation, not authentication. The owner key
  must not depend on a new session or source hash.
- Exactly two canonical revisions:0 selects the source archive;1 selects the actual next
  checkpoint archive. Retry reuses exact identities and bytes. No GC/random retry suffix.

compare normalized checkpoint objects, not their serialization to raw whitespace-bearing
source text. mkty_current_chapter may only receive a byte-identical no-op '9'.
Native WAIT appends ['act','wait',0] (the empty DOM data-value converts to Number0),
increments turn/moves and spends 5 stability without advancing home. Original bounded log
slice follows the unchanged model. Preserve the exact trace prefix and all untouched data.
A preflight oracle is not streamable evidence. Only the actual native captured checkpoint,
matched exactly to its expected transition, can become the next canonical archive.

Arm only the trusted native WAIT. Latch its immutable candidate and reentrancy guard before
calling the existing pause path, which saves recursively. Accept identical duplicates;
refuse a second distinct save. Wait until the outer original handler returns before async
storage work. A timer-before-WAIT mutation is retained and blocks this one-command test;
it is never discarded or represented as WAIT. Production clocks/cadence are unchanged.
A paused controller still receives lifecycle callbacks: install an explicit test-only
quiescence fence during async persistence. Deferred identical lifecycle work is bounded
and cannot enter original callbacks while incompatible helper/page/storage leases exist.
Completion, reward, failure-charge and network callbacks are tripwires at zero.

Durability and atomicity
Source archive staging is not atomic with owner publication. Seal and authenticate the
source first, then append revision 0 with expectedHead=null. That append's transaction
completion and readback select the import. Likewise seal/read back the captured checkpoint
before the CAS append selecting revision 1. Earlier orphan archives remain inert.
Recovery locates the fixed owner and authenticates exact referenced dependencies. Its
checkpoint comes only from the selected canonical archive. Original selected localStorage
values are still read one at a time as drift fences; they are not a restore fallback. It
never selects a newest archive or repairs missing/corrupt data.
Lost acknowledgment uses the same immutable request and readback, never replayed gameplay.

Monotonic invocation epoch is separate from the durable owner key. Identity/source drift
invalidates new insertion irreversibly. A transaction already dispatched can still commit
to its captured OLD scope after a switch; reconcile/quarantine that exact result read-only,
retain it and do not present it as success for another identity. No insertion-capable retry
after drift. Double-read equality cannot detect all A→B→A legacy writes. Exclusive old-realm
closure is a fixture precondition, not a production migration guarantee.

Rollback and remaining gates
Before revision 0, original source is unchanged and partial archives are inert. After a
new checkpoint commits, old JavaScript would read its stale mirror. Reverting old code
is NOT lossless rollback: an owner-aware reader or reviewed canonical export/handoff is
required. Keep both sources, no automatic mirror rewrite. Site-data deletion, OS eviction,
power loss and another device remain outside this browser-durability evidence.
Real activation still needs all-writer routing, old-client handling, signed server balance
ownership, legacy pending-claim preservation and cloud conflict/recovery decisions.
No test result here constitutes server anti-cheat, full campaign adoption or release approval.
