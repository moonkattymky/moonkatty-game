# Source-only bounded IndexedDB evidence adapter

This is an isolated archive experiment. No runtime imports, game listeners, production mapping, source retirement, reward/payment eligibility, completion, navigation, UI or deletion API are present. The owner has approved an eventual visible stop/retry when a completed result is not confirmed stored; its UX and runtime integration remain unimplemented and separately gated after adapter acceptance. The frozen design accurately records the earlier pending state. Storage acceptance never makes an over-limit recorder/proof admissible.

## Basis and boundaries

Implemented against the independently accepted design `finale-indexeddb-adapter-design-local-20261012/DESIGN.md`, SHA-256 `e0d7ee0a34465711e2b3dd25965a6309f2fa9399a2299f104bf53de663b441a0`, and frozen v3 archive SHA-256 `29d03d1e2343e4e0fa6ea7f09ec8f2375184e38409bbb8cf06e916f15f02551b`. Reference `store.cjs` SHA-256 `4ccd27d6b9840218d694ec71fd016158c08d7da05678802ba03e26ffc9280d5c`; reference coordinator SHA-256 `77c8c04a0049ecb07d497bb86fc39df7febdce0215c8a379b54fe0f013947ae7`.

The exact descriptor JSON property order, `ARCHIVE1` framing, UTF-16LE code units, SHA-256 domains, head/cursor formats, seal absence/presence, byte equality, duplicate-before-stale-guard ordering and fixed payload/page limits follow those inputs. Inputs must be ordinary data objects and ordinary dense component arrays; accessors/custom serialization are explicitly rejected before ownership. Shared and detached payload buffers are rejected.

This directory's Node vectors do not prove native IndexedDB behavior. Native fixture acceptance is a separate test-only Chromium/Playwright 1.58.2 CI task. No local browser, server or socket is needed by the vector suite. No WebKit, iPhone, Telegram WebView, OS/power-loss or production-readiness claim is made.

## Modules and API

- `contract.mjs`: portable byte and framing helpers. `describe`, `snapshotRequest`, `frame`, `unframe`, `metadataCharges`, byte/base64 helpers are synchronous. `descriptor`, `hash`, `chain`, `token`, `untoken`, `makeHead`, `headToken` use native asynchronous WebCrypto; their optional crypto/account parameters support deterministic vectors and reservation diagnostics. No handwritten cryptography or dependencies.
- `adapter.mjs`: `createAdapter({scope})`, fixed `DB_NAME`, `DB_VERSION`, and `STORES`. Construction binds one synthetic scope. A mismatch refuses before database access. Scope labels provide separation, not authentication.
- `coordinator.mjs`: `createCoordinator(adapter, readContext)`, `archive`, `assemble`. The only callback is a bounded live-context reader, plus the explicit source-admission predicate in `archive`, both outside IDB transactions. None grants gameplay authority.

An adapter has:

- `open()` → `{status:'open', createdNew}` or refusal. Other operations open lazily. `createdNew` means the upgrade was observed creating the prototype store, not proof it never held prior data. Site-data loss and first use cannot be distinguished without an external receipt.
- `appendSegment({descriptor, expectedHead, ordinal, offset, previousRoot, payload, seal?})` → committed, duplicate, conflict, refused or outcomeUnknown. Receipt fields match v3, except `acknowledgement:'idb-transaction-complete'` and `durability:'strict'`. The containing result also returns `currentHead`. Successful duplicate returns the original segment receipt and transaction-observed possibly newer head.
- `retry()` retries this instance's exact retained unknown request. New append admission across any scope in this helper-module realm refuses while an unresolved request is retained. There is no discard/rebind method or automatic retry.
- `readSegments({captureIdentity, throughHead, afterOrdinal=-1, maxBytes=65536})` → a bounded page of `{ordinal,offset,length,root,payload}` and exact pinned cursor, or refusal. No payload is returned before all collected integrity checks finish.
- `recover({scope, cursor=null, maxHeads=16, maxBytes=65536})` → bounded heads, membership watermark and next cursor. Each item has exact descriptor, head, sealed status, and acknowledgement/durability. Unsealed means incomplete. A watermark freezes membership only, not later pages' mutable heads.
- `close()` drains the instance and closes its connection. `state`, `createdNew`, `retainedBytes`, and `diagnostics` are read-only getters. Closing does not release a physical pending open/transaction/digest or silently discard ambiguous ownership.

The coordinator calls the adapter's optional internal preflight guard on append/retry before and after asynchronous preparation, outside transaction callbacks. Context is copied synchronously and checked using all three fields: scope, generation, exact source identity. A→B→A remains stale if generation/source identity changed. A returned storage result has `contextCurrent`, never permission to advance/retire/award. Retry of a stale coordinator context remains refused even after the original scope label returns.

`archive` first takes a bounded whole-artifact snapshot and calls the existing admission predicate. It segments only an already-admitted capture. `assemble` requires a sealed pinned item and an explicit bounded maximum; it returns exact bytes for the existing decoder/admission. Their full-artifact allocation, decoding, and assembly costs are separate from the adapter operation budget. C1 defaults remain 4,096 entries/196,608 bytes, hard 16,384/524,288; callback draft 128/32,768. Existing snapshot/proof limits are unchanged.

## Atomicity and lifecycle

All candidate descriptor/payload/head hashes happen before opening the append write transaction. Its four direct reads (head, target metadata, scope and global counter) determine all writes in the same overlapping six-store transaction. Request handlers are synchronous and enqueue dependent requests before returning. No await, promise continuation, digest, user callback, keepalive, or explicit commit occurs inside that request chain.

Writes use immutable `add` for metadata/payload and new head/index/scope; only existing head/scope/global counters use `put`. Maximum writes are six for a new capture, five for an existing capture. Strict is required and checked on the transaction object; no downgrade is offered. Individual request success never acknowledges commit. Only observed `complete` can produce committed; only observed `abort` proves this transaction did not commit. Native `QuotaExceededError` is separate from logical quota refusal.

A single module-realm identity gate includes preparation, open, transaction and post-read hashing. No unbounded queue exists. Timeout attempts abort if applicable; a thrown abort or absent terminal observation returns `outcomeUnknown`, not proof of rollback. Even after caller settlement, the slot and exact owned request remain reserved until the original physical request/transaction/digest terminates. Late events cannot settle the caller twice or release another operation. An unknown request remains available only for explicit exact retry; read/recover includes its reservation but does not silently discard it. If its owner is stale/closed, deciding whether/how to discard or transfer it remains outside this experiment's product policy.

Blocked open and open timeout abandon the logical request immediately, but IDB offers no open cancellation. A late upgrade is aborted, a late connection is closed, and the gate remains held until terminal open delivery. `versionchange`/explicit close drain immediately, including during preparation or schema validation. No reload, automatic migration, repair, upgrade-to-latest, replacement database, GC or deletion API exists. Missing/corrupt/unknown state is refused and retained.

Database `mkty_evidence_idb_prototype_20261012`, version 1, contains exactly six out-of-line, non-generating stores without secondary indexes: heads, segments, payloads, indices, scopes, meta. Initial schema and global marker are created together only from old version 0. Existing newer versions refuse downgrade. Startup's readonly schema/marker validation is counted separately by calling `open()` before measuring an operation; lazy first operations include it in their diagnostics.

## Accounting and diagnostics

Hard maxima: append payload 65,536; request metadata 4,096; lease 69,632; read payload 65,536; discovery JSON 65,536; direct positions 16; hash input 66,048; per-realm accounted transient reservation 393,216 bytes/encoded slots. Buffers/slots are reserved before adapter allocation. Hashes run serially, with native digest input copies separately counted. Request metadata is bounded before copying payload. Reads inspect bounded next metadata length before fetching payload. Discovery uses exact JSON sizing with a fixed-size cursor checksum placeholder, including inspected-but-not-returned next head position. It never scans or skips gaps.

The realm reservation covers retained request, operation slots, encoded metadata slots, fetched payload buffers, framing input, WebCrypto input copy, and response construction. `retainedBytes` reports request bytes only, not total retained JavaScript memory. The coordinator retains a small decoded context object and references to preexisting immutable strings (sourceIdentity <=4,096 UTF-8 bytes); these bounded references are excluded from byte-buffer accounting, alongside decoded object overhead. No encoded context copy is allocated. Any future encoded context allocation would require its own reservation and does not change logical R here. Discovery reserves two descriptor byte slots plus 4,096 bytes per retained head; the temporary reserialization/token workspace is within the operation's 16,384 fixed slots and hash reservations. The logical stored head charge remains the reference's three descriptor byte slots plus 4,096. This is encoded-slot/buffer accounting, not measured JS heap/RSS. Native IDB clones/indexes/allocators, decoded object overhead, caller-retained completed results and full artifact ownership/assembly are explicit exclusions. IDB has no size-limited get; same-origin corruption may force a large native deserialization before rejection. This does not defend against hostile same-origin code or arbitrary numbers of realms/contexts.

Logical committed quota is 8,388,608 with <=128 captures and initial global charge 384. Charge delta is `P+4096+(newCapture ? H+I : 0)+(newScope ? K : 0)`, with `H=3*descriptorBytes+4096`, reference escaped index `I>=2048`, and `K=384+UTF8Bytes(JSON.stringify(scope))`. Before writes both committed delta and `C+P+4096+H+(newCapture ? I : 0)+K+384+R` must fit Q. R is this realm's live lease. Transactional global counters prevent logical record overcommit across contexts; no global browser heap/quota reservation is claimed. The reference fake's all-context transient accounting/exhaustion threshold is intentionally not claimed.

`diagnostics` returns a snapshot, no user callbacks: transaction/direct read/write counts, individual request errors, observed terminal, bounded event sequence, hashes/chain hashes/input/native-copy bytes, request/comparison/output bytes, staging/logical peak, live/peak accounted reservation, zero enumerations and zero historical append payload reads. Output payload arrays reuse already-collected native-read buffers; there is no second adapter payload copy. Request-error diagnostics alone never establish rollback. Representative reasons: busy, retry-pending, stale-context, scope-mismatch, logical-quota, native-quota, unsupported-durability, open-blocked, open-timeout, operation-timeout, terminal-unobserved, schema-mismatch, unsupported-version, insecure-context, indexeddb-unavailable, webcrypto-unavailable, webcrypto-sha256-unavailable, storage-unavailable, adapter-closed, and precise malformed/integrity/page-budget errors.

## Test-only seam and verification

`createTestAdapter({scope,indexedDB,crypto,secureContext,openRequestFactory,watchdogMs})` uses the same implementation. Defaults are native globals and 15,000ms, with watchdog bounded 1–60,000ms. The optional factory is called as `openRequestFactory(fixedName,1)` outside a transaction; it is solely for the approved real blocked-open fixture translating to version 2 while another raw connection retains v1. No public database-name/version override exists. Tests may externally instrument native IDB events/methods or provide delayed native WebCrypto wrappers. No injection grants false commit acknowledgements.

Run socket-free vectors with `node tests/evidence-indexeddb.cjs`. The 2,014-assertion source pass checks independent Node SHA-256/base64/byte framing oracles, 64 UTF-8/UTF-16/surrogate/BOM/escaping cases, roots/tokens/cursors, payload/seal limits, accessor rejection, caller-mutation ownership, context/scope refusal and EventTarget-only abandoned-open bookkeeping. EventTarget checks are wrapper unit tests, not native IDB simulations or durability evidence. Native abort, two-page CAS, reload/profile restart, quota, legacy-writer compatibility, lifecycle and corruption proof remain the separate CI acceptance matrix.

Current game storage clear/retry, StoryPlan rewrite and cloud snapshot/restore do not manage this independent database. Preservation against those operations is a retention limitation, not an approved deletion/backup policy. Browser-wide site-data clearing, eviction, profile/device loss and power failure can lose the data. Strict is a browser durability hint, not a hardware flush measurement. A graceful persistent-profile restart proves only that tested boundary.
