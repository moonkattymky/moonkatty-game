# Source-only continuous phase session, Step B

`createFinalePhaseSession` is an isolated test candidate. The game does not import
it. It owns one disposable guest sequence: chapter 8 decode and trajectory, then
chapter 9 convoy, docking and gate. Original handlers and game files are unchanged.
Chapter prerequisites are synthetic; this is not proof of an earned campaign or
server reward authority. Step C must establish native continuous gameplay separately.

## Ownership and transitions

The session shares the existing permanent per-realm owner with the v1 gate.
Startup requires bounded empty archive recovery, physical adapter idle, exact
fixed guest/background records and no pending cloud restoration. Nonempty or
reloaded archives are inspection-only. No reset, automatic settlement, source
removal, account migration or legacy-claim policy is provided.

Capture leaves the board and revokes its handlers before copying or awaiting.
The exact chapter context is streamed once; each bounded phase packet is appended
and compared through exact sealed native readback. Explicit Continue invokes the
original callback once. Successor descriptors are staged; the original field is
opened later, paused, only after the previous writer's exact persistent drain.
Retry saves or reads the same pending result; it never replays an award callback.

The fixed original writer observations cover five dispatches, five opens, entry
navigation/confirmation and epilogue completion. The public original chapter-9
story entry is wrapped; its preceding cinematic/unlock route is not integrated.
The actual risk dialog's one-use Confirm/Cancel closures remain authoritative.
Cancel closes the dialog without story writes; duplicate/stale handles are inert.

The actual chapter-space -> operations -> story entry wrapper is included. The
disposable fixture may explicitly pin both `mkty_operations_8_v1` and
`mkty_operations_9_v1` in `preState`, using exactly this canonical property order:
`{"version":1,"n":8,"seed":731,"round":3,"phase":"core","input":null,"confirmed":false,"actions":0,"hints":0,"errors":0,"seconds":0}`
(chapter 9 changes only `n`). These are synthetic already-prepared prerequisites,
not evidence that the legacy planning boards were played. No other seed, counter,
field, property order or whitespace is admitted. Both omitted keys or both explicit
nulls preserve the old absent-record case; a partial/mixed pair is refused. With
absent chapter-9 operations, the actual wrapper starts planning and its unexpected
write is rejected. Planning remains outside this successful session.

Both logical and native operations pins are checked at begin and immediately
before original callbacks, before `operations.read()` can parse or cache a changed
record. Each final dispatch allows the unchanged `MKTYOps.complete` phase-only
`core` -> `complete` rewrite after the life completion timestamp and before the
story completion rewrite. Prepared finals have twelve observed writes; absent
records keep the old eleven-write no-op case. The completed chapter-8 record is
carried through chapter 9, and both completed records are verified through final
epilogue drain. Extra operations writes, including the original pagehide save
outside a writer, remain rejected. This does not add reload or pagehide authority.

Chapter-8 context retires only after its exact writer drains. A bounded UTF-16
SHA-256 witness rechecks its later native correspondence before chapter-9 entry,
confirmation, opens, continuation and epilogue. Transient read failures retain
only the same uninvoked fixed action. The final chapter-9 writer and exact target
remain owned until epilogue completion and final native drain. A digest witness
relies on collision resistance; it is not trusted gameplay evidence.

A test-only capture-phase input fence prevents Resume, Submit, pointer/range and
keyboard listeners from mutating the inactive board while persistence is pending.
It is not an API sandbox. Noncancelable native events can already alter a control's
DOM value; only native testing can establish actual default-action behavior.

## Existing bonus and resource limits

The bounded precision observer mirrors legacy.js `precise()` count/total over
chapter 1–8, without StoryPlan normalization or proof unpacking. Each source and
parsed representation must fit 65,536 bytes and at most eight task entries. Only
two scalars survive. The existing gate bonus is min(20, count * 2), followed by
unchanged cargo/event additions. Changed counts block before relevant callbacks;
same-count changes to earlier chapter histories are not whole-history equality.

All limits remain unchanged. The peak modeled representation schedule is:

- Adapter + metadata + raw + retained current context: 557,056 bytes
- Original checkpoint scratch + outer/inner story slots: 196,608 bytes
- Original read/parse/restore workspace OR independent projection: 196,608 bytes
- Sole exact provisional/latest story target: 65,536 bytes
- Total: 1,015,808; ceiling: 1,016,832; margin: 1,024 bytes

Projection borrows its three slots only after the underlying facade and its
synchronous listeners return, and restores the read lease before original code
resumes. PLAYING saves also have an enclosing callback/read lease. Raw reservation
continues through staged successor handoff. Every await checks owner, epoch and
physical storage state; buffer references are dropped before releasing their slots.

Operations pins and exact expected writes are included in the unchanged 8 KiB
small-value cap and measured writer/session metadata. Each canonical core record
is 262 UTF-16 bytes; each complete record is 270 bytes. The existing 32 KiB shared
metadata reservation now explicitly includes 540 bytes for the original two
cached parsed records throughout the session (`s` and `run` alias those records),
plus 540 bytes for a possible pagehide save's stringify argument and facade
old-value read before its unexpected write is rejected. Each writer also charges
540 bytes for the fixed-string comparison scratch. The helper retains no parsed
graph or canonical template string. Original synchronous operations read, cache
comparison, parse and completion serialization use the existing 196,608-byte
original-read lease. No limit or total reservation is increased, and the 1,024-byte
ceiling margin is unchanged. This accounting requires a fresh original operations
cache containing only these fixed chapter-8/9 records; arbitrary operations,
planning and assignment boards are excluded.

This ledger is not a browser heap/RSS bound. It excludes object headers, GC timing,
native storage internals, DOM/render allocations and arbitrary third-party code.
Oversize native strings can be rejected only after the platform returns them.
Terminal user field-exit navigation leaves this finite successful-session resource
contract; downstream chapter rendering is not covered by its ledger.

## Remaining gates

Node/VM tests use synthetic clocks, DOM routing, completed checkpoints and storage
transport doubles. They do not establish native input, native durability, earned
continuous gameplay, phone behavior, OS eviction resilience or cross-tab authority.
Original source-removal-before-award and points-before-marker crash prefixes remain
inspection-only; no reload reward replay or exactly-once financial claim is made.

Large legal contexts above the existing 65,536 representation bound and long raw
phase traces above existing codec/packet caps remain refused with source preserved.
This is not an unlimited-session or nine-chapter production storage solution.
